# Смена статуса хотелки — успех не выглядит отказом (ANO-208)

Найдено 28.09 при замере A5 (ANO-107). Вид — «причина известна, чиним», этот спринт (план спринта, раздел 7). На «Что с капиталом» — регрессия #108 (ANO-141), влит 28.09.

## Что сломано

Замер 28.09 на стенде `ddb4cee` — код `main` после #108 и #109. Раздел «Как мерил».

| где | запросы | на экране |
|---|---|---|
| «Хотелки» → примерка → «Параметры» → «Отложить», хотелка и копилка | `PATCH …/wishlist-status` → 200 | «Ошибка примерки: Failed to execute 'json' on 'Response': Unexpected end of JSON input»; строки остаются в примерке, перечитывания нет |
| «Что с капиталом» → карточка → «Отклонить» | `PATCH …/wishlist-status` → 200 | «Не записалось — попробуйте ещё раз», карточка на месте; после перечитывания пропадает — отклонена |
| «Что с капиталом» → «Зафиксировать» → «Зафиксировать без конверсии», копилка | `PUT /funds/{id}` → 200, `PATCH …/wishlist-status` → 200 | «Не записалось — попробуйте ещё раз», диалог открыт; на сервере — зафиксирована |
| «Что с капиталом» → «+ Добавить хотелку» → «Копилка» | `POST /funds` → 200, `PATCH …/wishlist-status` → 200 | диалог закрылся — случайно: на отказе он перечитывает список, блок уходит в загрузку, и диалог размонтируется вместе со строкой ошибки |

**Почему.** Ручки статуса хотелки — `PATCH /events/{id}/wishlist-status` и `PATCH /funds/{id}/wishlist-status` — единственные две `void` без `@ResponseStatus(NO_CONTENT)`: отвечают `200` с `Content-Length: 0`. Клиент (`api/client.ts`, `request`) пустое тело прощает только при 204, на любом другом успехе зовёт `res.json()` — и падает на пустом теле. Запись прошла, экран говорит, что нет.

**С каких пор.** Примерка — с появления ручек статуса (`6bd29c4`). «Что с капиталом» — с #108: до неё обработчик глотал любую ошибку и перечитывал список, и успех выглядел успехом. Спека #108 мерила «Отклонить» только с оборванной связью, успешный путь — нет.

## Решение

**Клиент, одно место: у успешного ответа нет тела — нет и данных, как у 204.** `request` читает тело текстом и разбирает JSON, только если тело есть. Отдельная проверка 204 становится частным случаем того же правила.

**Почему не сервер.** Две ручки можно перевести на 204, как остальные `void`. Но 200 без тела — законный ответ HTTP, и клиент остался бы хрупким к следующей такой ручке: один забытый `@ResponseStatus` — и тот же дефект на другом экране. Правка в клиенте закрывает все пути сразу, сервер не трогаем.

**Что станет на экране:** «Отложить» и «Вернуть в обсуждение» в примерке — строка уходит или отпирается, как задумано; «Отклонить» в «Что с капиталом» — карточка пропадает, ошибки нет; «Зафиксировать без конверсии» — диалог закрывается; добавление копилки и кредита — без скрытого отказа.

## Как мерил

* **Стенд:** `GET /api/v1/version` → `ddb4cee`; бандл в странице — `index-dc7a90ff.js`, тот же, что отдаёт стенд; адреса страниц — в обход кэша (`?v=…`).
* **Ответ ручки:** `curl -i -X PATCH …/events/{id}/wishlist-status` → `HTTP/1.1 200`, `Content-Length: 0`.
* **Пробы** — ручками экрана создания: хотелки `POST /events/wishlist`, копилка — `POST /funds` и `PATCH /funds/{id}/wishlist-status` → `OPEN`. Одна копилка — через сам диалог «+ Добавить хотелку». Скрипт — вне репозитория.
* **Экран:** кнопки нажимал в странице; запросы и статусы — подменой `fetch`: запрос уходит как есть, адрес и статус пишутся в журнал страницы. Текст на экране — текстом страницы.
* **Что осталось на сервере:** примерка и «Что с капиталом» — их ручками, `POST /pocket/sandbox` и `GET /wishlist/simulation`: отклонённая проба не приходит ни в одну.
* **После замера** пробы удалены: копилок 11, свободно −197 212 — как до.

## Чего не делаем

* **Ручки статуса на 204** — раздел «Решение».
* **Английский текст настоящего отказа** в примерке — «Ошибка примерки: …» с текстом сервера (`Wishlist.tsx`, `reason(e)`): болезнь ANO-203, не этот путь.
* **Пути назад у отложенной хотелки** — ANO-107, следующая задача: она пойдёт через ту же ручку.

## Чего не ловит

* **Успех с телом, которое не JSON.** Такого ответа у сервера нет: он отдаёт JSON или ничего. Разбор упадёт, как и раньше.
