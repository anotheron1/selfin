Сейчас в `docs/superpowers/specs` 51 спека `*-design.md`. Раздел «Правила продукта — сверка» есть у 8, «Как мерил» — у 1, слово «замер» или «перемер» встречается в 25.

## 2. Решение

`tools/spec-check.mjs [<база>]` — Node без зависимостей, как остальные инструменты. Берёт спеки `docs/superpowers/specs/*-design.md`, добавленные, изменённые или переименованные относительно базы (по умолчанию `origin/main`), и для каждой проверяет:

* есть заголовок раздела «Правила продукта — сверка» — любого уровня от `##` до `####`, номер перед ним допускается;
* если в тексте есть «замер» или «перемер» — есть заголовок раздела «Как мерил».

Выход 0 — если проблем нет. Проверяется только наличие раздела, не его содержимое: содержимое читает ревью.

Старые спеки не трогаются: правило действует на спеку, когда её меняют.

Джоба «Спеки — сверка правил и «Как мерил»» в `ci.yml` гоняет тот же скрипт с базой PR. Она встаёт в проверки PR, поэтому её видит и `tools/pr-ready.sh` — отдельного пункта в нём не нужно.

## 3. Правила продукта — сверка

Правка — инструмент разработки, экранов, расчёта и данных пользователя не касается.

| правило | как соблюдено |
|---|---|

## 6. Как мерил

Область — все спеки `docs/superpowers/specs/*-design.md` в `main` на 26.09, `9639be8`. Выдача не обрезалась, считалось `wc -l`:

```bash
ls docs/superpowers/specs/*-design.md | wc -l                                   # 51
grep -l "^## Правила продукта — сверка\|^## [0-9]*\.* *Правила продукта — сверка" \
  docs/superpowers/specs/*-design.md | wc -l                                    # 8: семь «## Правила…», одна «## 6. Правила…»
grep -l "^## .*Как мерил" docs/superpowers/specs/*-design.md | wc -l             # 1
grep -l "замер\|Замер\|перемер\|Перемер" docs/superpowers/specs/*-design.md | wc -l   # 25
```

Регистр — оба варианта первой буквы перечислены явно: `grep -i` в здешнем Git Bash кириллицу не складывает.

## 7. Выполнено

**Тесты** — 11, сначала красные: модуля не было. Тест скрипта ворот, который читает настоящие workflow, увидел новую джобу CI и покраснел — ожидание дополнено. Всего в джобе «Инструменты — тесты» 97 тестов.

**Мутации на итоговом коде — 10 из 10 пойманы своим тестом**, контроль без подмены зелёный: раздел сверки не проверяется; «Как мерил» не проверяется; «Как мерил» требуется и без замера; засчитываются слова раздела в тексте; номер перед заголовком не допускается; заголовок только уровня `##`; заголовок через перевод строки; блоки кода не вырезаются; HTML-комментарии не вырезаются; замер с заглавной не находится. Мутации скрипта ворот на итоговом коде — 66 из 66.

Прогонщик мутаций подвёл дважды, оба раза это видно в выводе. `String.replace` со строкой замены понимает `` $` `` как «текст до совпадения», и мутант с таким шаблоном не загружался вовсе — замена переведена на функцию. После переключения веток git выгрузил файлы с CRLF, и многострочные искомые куски перестали совпадать — исходник перед мутацией приводится к LF.

**Красное в CI на подсаженной поломке** — черновой PR #89 поверх ветки этого PR, со спекой без раздела сверки и с замером без «Как мерил». Джоба «Спеки — сверка правил и «Как мерил»» красная (прогон 36266841786): «нет раздела «Правила продукта — сверка»; есть замер или перемер, нет раздела «Как мерил»». Остальные проверки зелёные. #89 закрыт без вливания.

**Ревью Codex на #88 — P2, подтвердилось.** В шаблоне заголовка стоял `\s`, и он захватывал перевод строки: «##» на одной строке и «Правила продукта — сверка» на следующей сошли бы за заголовок. Теперь между знаками заголовка и названием — только пробелы и табы, строка с CRLF по-прежнему находится.

**Второе ревью Codex на #88 — P2, подтвердилось.** Заголовок в блоке кода или в HTML-комментарии засчитывался за раздел, хотя Markdown его заголовком не рендерит — а спека о самой проверке вполне может показать заголовок примером. Перед поиском заголовков блоки кода и комментарии вырезаются. На этом по #88 полировка остановлена — правило «знать грань».

**На истории** — `node tools/spec-check.mjs 36d007b~1`, то есть всё, что влито после ветки #80: красный. Спека сторожа словаря, которую правил #83, — без сверки и без «Как мерил»; спеки #74, #73, #76 — с перемером, но без «Как мерил». На этой ветке — чисто: изменена одна эта спека.
