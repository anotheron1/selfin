# Копилка без счёта — доля остатка основной карты (Р10: ANO-212)

PR 3 спринта 4 (`2026-10-03-sprint-4-plan.md`, раздел 3). Решение владельца 03.10 — карта C1 (`2026-10-03-money-answers-map-design.md`), Р10-А: деньги копилок без счёта лежат на основной карте. Две развилки спеки решены 05.10 — раздел «Решения 05.10». Спека и план — одним документом.

## Что на экране

Стенд `090d539` (`main`), 05.10, через API продукта. Копилка без счёта «кеке», основная карта — 54 900 по последней сверке, наличные «Эталон» — 5 000. Скрипт — «Как мерил»; после него стенд вернулся к исходному.

| шаг | «на счёте» | основная карта | свободно | в «кеке» | капитал | сверка |
|---|---|---|---|---|---|---|
| исходно | 59 900 | 54 900 | −190 312 | 0 | 2 668 177 | — |
| «Пополнить» «кеке» на 10 000 | **49 900** | 44 900 | −200 312 | 10 000 | 2 668 177 | — |
| сверка карты числом банка, 54 900 | 59 900 | 54 900 | 27 800 | 10 000 | **2 678 177** | «selfin насчитал 44 900», **дрейф +10 000** |

* С карты ничего не уходило — деньги «кеке» отложены в уме, банк их видит на карте. Перевод же вычел их из остатка карты, а сверка вернула: одни и те же 10 000 лежат и в карте, и в копилке. Капитал вырос на 10 000 из ничего, в истории сверок — ложный дрейф.
* Свободные после сверки выросли на 228 112: 218 112 — брони с прошедшей датой, которые снимает сверка той же датой (ANO-79), и 10 000 — задвоение копилки.

## Решение (Р10-А)

**Копилка без счёта — доля остатка основной карты.** Безадресные факты и так относятся только к основной карте (спека счетов, §5.1), поэтому «доля основной карты» — не новое допущение, а то, куда эти деньги уже записывались.

* **«На счёте» — число банка.** Перевод в копилку без счёта и обратно остаток карты не меняет: деньги остаются на ней. Правило «сколько факт двигает остаток» живёт в одном месте — `AnchorWindow.balanceEffect`: доход — плюс, расход — минус, перевод в копилку — ноль. Его зовут все три места, которые суммируют факты: остаток счёта (`AccountBalanceService.factsDelta`), шаг 1 ядра (`PocketEngine.calculate`) и дрейф сверок (`BalanceCheckpointService.findAll`).
* **Свободно — остаток минус копилки.** Ядро вычитает накопленное в копилках без счёта на сегодня строкой «Уже в копилках» — сразу после «На счёте». Сумма — движения копилок без счёта по сегодня, тот же запрос, что у капитала (`sumEnvelopeFundsByTransactionDateLessThanEqual`, через `AccountBalanceService.envelopesAt`). Траектория начинается с остатка минус копилки, поэтому планы, брони и минимум считаются как прежде. Планы перевода в копилку и взносы зафиксированных копилок по-прежнему уменьшают свободные. Пока сверок нет, свободные считаются ровно как сейчас: остаток вырос на переводы, строка их вычла.
* **Календарь, точка «сегодня»,** называет и копилки, иначе «на счёте» карточки снова разошлось бы с её числом (Р6): «сегодня · после броней и копилок −168 212 ₽ · брони с прошедшей датой −218 112 ₽ · уже в копилках −10 000 ₽»; без броней — «сегодня · после копилок … · уже в копилках …». Без копилок — как было.
* **Сверка числом банка** сравнивается с остатком, в котором деньги копилок есть: дрейфа нет, «selfin насчитал» — то же число, что в банке.
* **Капитал**: ликвид — остатки счетов и вклады; копилки без счёта уже внутри остатка карты и отдельно не прибавляются (`CapitalService.cashLiquidAt`).
* **Прошлые месяцы «Стратегии»** — остаток счетов минус копилки без счёта на конец месяца: смысл точки прежний («остаток без копилок»), линия не прыгает на стыке с ядром.
* **«Удалить копилку → потрачено на цель»** (решение 1) — трата сегодняшним днём на накопленное, с именем копилки, в системной категории «Цели». Деньги уходят с карты сейчас — тратой, а не переводами, которые их только откладывали. Поэтому переводы больше не переименовываются в трату: иначе журнал показал бы «Отпуск» дважды — переводами и тратой. Движение копилки на минус накопленное — как было: оно обнуляет копилку и хранит её историю для прошлых дат.
* **Слова в продукте.** Справка кармашка: в «Что это за число» — что счёт идёт от остатка за вычетом уже отложенного в копилки; в «Срок, оговорки и остаток» — что «на счёте» деньги копилок включает и сверять надо числом банка как есть. Подсказка копилки без счёта на «Целях» (`lib/fundAccount.ts`) — что это часть денег основной карты: перевод откладывает их из свободных, а с карты они не уходят. Подсказка привязки копилки с деньгами к счёту — что переведённое снова свободно на основной карте, а не «не входит в капитал».
* **Копилки на счёте** — без изменений: их деньги — остаток своего счёта (§3.3).

## Решения 05.10

1. **«Потрачено на цель» — А, решение владельца 05.10** («Давай А»): запись-трата сегодняшним днём на накопленное, с именем цели. Отвергнуто — ничего не писать, а покупку записывать обычной тратой: после «потрачено» деньги вернулись бы в свободные, пока человек не запишет покупку сам.
2. **Имя строки — «Уже в копилках». Принято заочно, по разрешению владельца 05.10** («разрешаю заочно принимать рекомендуемые решения»). В расшифровке уже стоит «Взносы в копилки» — будущие планы. «В копилках» и «Отложено в копилки» рядом с ней читались бы как те же взносы; «уже» отделяет отложенное от того, что только будет отложено.

## Старые «потрачено»: миграция V29

До правки «потрачено» уменьшало остаток карты переводами, а копилку обнуляло движением без траты. С правкой переводы остаток не двигают, и без траты деньги таких копилок вернулись бы на карту — в «на счёте», в свободные и в капитал.

`V29` пишет каждой такой копилке трату, какую с правки пишет сам продукт: на сумму движения-списания, тем же днём, временем записи движения, с именем копилки, в категории «Цели». Время записи нужно правилу дня сверки (ANO-82): трата, записанная до сверки того же дня, внутри числа банка, после — нет.

* **Как опознаётся:** движение на минус у удалённой копилки без счёта, у которого нет события с тем же ключом. «Вернуть» пишет перевод с ключом движения, «Снять» — тоже; без события остаются только «потрачено» и компенсации `V24` — тоже потраченные деньги копилок, удалённых до ANO-86.
* **Числа истории не меняются.** Пример: сверка 100 000, перевод 10 000 в «Отпуск», через четыре дня «потрачено». До правки: карта 90 000 с дня перевода, капитал 90 000 со дня «потрачено». После правки и `V29`: карта 100 000 до «потрачено» и 90 000 после, копилки вычитаются из свободных и прошлых месяцев «Стратегии» — свободные, капитал и прошлые точки совпадают с прежними.
* **Переименованные переводы** таких копилок получают прежнее описание «В копилку: <имя>» — то, что пишет «Пополнить». Переименование делала прежняя ветка «потрачено» ради того, чтобы журнал назвал деньги тратой; теперь трату называет сама трата.
* **Категория «Цели»** заводится, если её нет, — системной, как «Кредит».

## Не закрывает

* Деньги копилки без счёта на другой карте или наличными — Р10-Б отвергнут: все копилки без счёта считаются долей основной карты.
* Сверка той же датой снимает брони с прошедшей датой (ANO-79) — отдельная тема, не Р10.
* **Сверки, введённые за вычетом копилок.** Кто, зная о задвоении, вводил число банка минус копилки, после выкатки увидит свободные меньше на сумму копилок — до первой сверки числом банка. Сверки задним числом продукт не правит: какое число вводилось, он не знает.
* **Перевод к плану, записанный до ANO-201 без движения копилки,** больше не уменьшает остаток: копилка его не получила, деньги остались на карте. Раньше они пропадали из обоих мест.
* Имена копилок под строкой «Уже в копилках» не выводятся — они на «Целях». Добавить, если спросят.
* Категория «Цели» ищется по имени, как «Кредит» и «Переводы в копилки»: своя категория человека с таким именем станет категорией этих трат.

## План

1. По каждой строке таблицы: тест красный — правка — зелёный. Бэк: правило, ядро, сборщик, капитал, «Стратегия», «потрачено», миграция. Фронт: расшифровка, календарь, тексты.
2. Мутации на итоговом коде, каждая своим тестом; полный прогон бэка и фронта.
3. Стенд «до» и «после» по скрипту сценария; миграция — на данных стенда.
4. PR без метки «меняет-данные». Проверка миграций в CI сравнивает записи базы — строки и суммы по таблицам, — а не вычисленные числа. Правка меняет вычисления, а записи меняет только `V29`. Сеятель делает «вернуть», но не «потрачено», поэтому на его данных `V29` ничего не пишет.

## Характер плановой строки

Не касается: правка меняет, как факты двигают остаток, а не какие планы держит ядро. Трата «потрачено на цель» — факт; брони, ожидания и хотелки считаются как прежде.

## Как мерил

* **Стенд** — `GET /api/v1/version`.
* **Через API**, скрипт ниже: `POST /funds/{id}/transfer` — «Пополнить»; `POST /balance-checkpoints` — сверка; уборка — `DELETE /balance-checkpoints/{id}` и `DELETE /events/{id}` перевода.
* **Числа:** «на счёте» и свободно — `GET /pocket`; основная карта — `GET /accounts`; капитал — `GET /capital/summary`; копилка — `GET /funds`; сверка — `GET /balance-checkpoints`. Через SQL — ничего.

## Скрипт сценария

`node scenario.mjs` — стенд на `localhost:8081`; печатает шаги и убирает за собой.

```js
// PR 3 (Р10, ANO-212): копилка без счёта и сверка карты числом банка — замер через API продукта.
// node scenario.mjs — шаги и уборка; после неё числа обязаны вернуться к исходным.
import { randomUUID } from 'node:crypto';

const API = 'http://localhost:8081/api/v1';
const FUND = 'кеке';
const today = new Date().toLocaleDateString('sv-SE', { timeZone: 'Europe/Moscow' });

async function call(method, path, body) {
  const r = await fetch(API + path, {
    method, headers: { 'Content-Type': 'application/json', 'Idempotency-Key': randomUUID() },
    body: body ? JSON.stringify(body) : undefined,
  });
  const text = await r.text();
  if (!r.ok) throw new Error(`${method} ${path} → ${r.status} ${text}`);
  return text ? JSON.parse(text) : null;
}

async function measure(step) {
  const pocket = await call('GET', '/pocket');
  const card = (await call('GET', '/accounts')).find(a => a.isDefault);
  const cap = await call('GET', '/capital/summary');
  const oct = (await call('GET', '/strategy/timeline?horizonMonths=12')).points.find(p => p.yearMonth === today.slice(0, 7));
  const fund = (await call('GET', '/funds')).funds.find(f => f.name === FUND);
  const cps = await call('GET', '/balance-checkpoints');
  const last = cps.filter(c => c.accountId === card.id).sort((a, b) => (a.createdAt < b.createdAt ? 1 : -1))[0];
  console.log(`${step.padEnd(30)} | «на счёте» ${pocket.currentBalance} | основная карта ${card.balance} | свободно ${pocket.pocket} | в «${FUND}» ${fund.currentBalance} | капитал ${cap.total} (ликвид ${cap.liquid}) | «Стратегия» ${oct.yearMonth} ${oct.balance} | сверка ${last.date}: ввод ${last.amount}, selfin насчитал ${last.computedBalance}, дрейф ${last.drift}`);
  return { card, fund, last };
}

const { card, fund } = await measure('0. исходно');
await call('POST', `/funds/${fund.id}/transfer`, { amount: 10000, confirm: true });
await measure('1. перевод 10 000 в копилку');
const cp = await call('POST', '/balance-checkpoints', { date: today, amount: Number(card.balance), accountId: card.id });
await measure(`2. сверка карты: ${card.balance} из банка`);

// Уборка: сверку — удалить; перевод — удалить записью журнала, вместе с движением копилки.
await call('DELETE', `/balance-checkpoints/${cp.id}`);
const events = await call('GET', `/events?startDate=${today}&endDate=${today}`);
for (const e of events.filter(e => e.type === 'FUND_TRANSFER' && e.targetFundId === fund.id)) {
  await call('DELETE', `/events/${e.id}`);
}
await measure('3. убрано');
```
