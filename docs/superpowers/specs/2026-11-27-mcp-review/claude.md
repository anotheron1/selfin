# Ревью MCP Selfin: правила продукта, слова, видение, процесс

27.11.2026. Ветка `codex/selfin-mcp-http`, голова `4ba92c1`, против `origin/main`. Линза: 13 правил продукта, слова экрана, чек-лист видения (раздел 10), спеки и процесс. Протокол, OAuth, деплой в деталях и правильность денег смотрят Codex и Gemini — здесь только то, где они пересекаются с правилами.

**Как проверял.** Я читал код `mcp/` и маршрут бэкенда. Для сравнения брал те места фронта и бэка в той же голове, откуда берутся экранные слова: `lib/gapMode.ts`, `lib/breakdownRows.ts`, `lib/quickAdd.ts`, `lib/priority.ts`, `lib/planFact.ts`, `pages/Analytics.tsx`, `PocketEngine`, `ExpectationMatch`, `VisitMarks`. PR #246–#248 читал через `gh`, Linear — поиском. **Ничего не запускал**: ни стенда, ни тестов, ни клиента. Всё, что сказано о поведении, выведено из кода. Что не проверено — помечено словом «гипотеза».

## Сводка

1. Четыре запрета прямо не нарушены. Инструментов лимитов нет, план-факт — отдельный инструмент «только по явной просьбе», точность не обещается, пейволла нет. Но защищают это две фразы в двух описаниях. **Инструкций сервера нет совсем**, поэтому бюджет по категории из `search_expenses` модели ничто не запрещает.
2. Сильнее всего нарушены **правила 8 и 13**. `get_available_money` отдаёт запасные подписи бэка, которые экран нарочно не показывает: «Остаток на счёте (чекпоинт 03.11 + движение)» — ровно текст, проваливший проверку A4. Оговорки после итога обрезаны, включая «погасить кредитки». Итог не назван по состоянию («Не хватает», «Придётся взять из НЗ»), а поле называется `available`, то есть «доступно» — слово, которое правило 13 прямо отвергает.
3. Правильность в точках пересечения с правилами держится. «Свободно» берётся из того же `GET /pocket`, что и шапка. Примерка — штатная `POST /pocket/sandbox`. «Сегодня» — по календарю бэка. Запись идёт только после формы подтверждения. Характер плановой строки сохраняется.
4. Из 30 пунктов чек-листа видения: 7 — есть, 6 — сделано иначе (четыре из них — не хуже или лучше), 14 — частично, 3 — нет. Главная работа вехи по видению — пачка трат из выписки и обновление остатка — отсутствует. Вместо неё сделано планирование из истории с сериями, которого в видении почти нет.
5. Спеки вехи в репозитории нет: есть README и рабочие заметки вне репозитория со ссылками на `C:/...`. Задач в Linear нет, решений владельца по развилкам нет. При этом реализация уже выбрала иначе по 7.1, 7.3 и 7.7. **Вердикт: #247 — да сейчас; #246 и #248 — да после спеки с решениями владельца и задачи в Linear, а `deploy/` — отдельно.**
