## Как

**Папка `deploy/`** — всё, что нужно серверу кроме образов: `docker-compose.yml`, `Caddyfile`, `.env.example`. На сервере — клон репозитория (он открытый), `cd deploy`, `.env` по шаблону, `docker compose pull && docker compose up -d`. Реалм берётся из `../keycloak/selfin-realm.json` того же клона.

* **Caddy впереди** — сам получает и продлевает сертификат Let's Encrypt для `SELFIN_DOMAIN`, проставляет `X-Forwarded-Proto`. Порты 80 и 443 — переменными: если у друга они заняты его сайтом, встаём за его прокси (решить в шаге 6 по ответу друга).
* **Один адрес:** приложение — на `/`, Keycloak — под `/auth` (`KC_HTTP_RELATIVE_PATH`). Снаружи закрыты: консоль администратора (`/auth/admin`), реалм `master` и консоль учётной записи (`/auth/realms/selfin/account`) — через неё учётная запись заводится мимо согласия (шаг 4).
* **Консоль администратора — с самого сервера:** Keycloak слушает `127.0.0.1:8180` машины, `KC_HOSTNAME_ADMIN` — этот адрес; с компьютера владельца — SSH-туннель. Туда же ходят команды `tools/` (`SELFIN_KC_ADMIN`).
* **Keycloak в боевом режиме:** `start --import-realm`, `KC_HOSTNAME` — публичный адрес с `/auth`, `KC_PROXY_HEADERS=xforwarded`, `KC_HTTP_ENABLED=true` за прокси, пароль администратора — из `.env`; своя база отдельным контейнером.
* **Реалм как код:** к адресам стенда добавлены `${SELFIN_PUBLIC_URL:…}/login/oauth2/code/keycloak` и `${SELFIN_PUBLIC_URL:…}/login`: на сервере — его адрес, на стенде без переменной — адрес стенда. Подстановку делает импорт реалма при первом старте Keycloak.
* **Сервер за HTTPS-прокси:** `server.forward-headers-strategy=native` — Tomcat верит `X-Forwarded-Proto` от внутренних адресов (сеть Docker); nginx фронта передаёт схему прокси, а без прокси — свою (`map`). Тогда адрес возврата из Keycloak — `https://…`, а cookie сеанса — `Secure`. Порт nginx берёт из `Host` и передаёт `X-Forwarded-Port`: получив схему без порта, Tomcat ставит порт схемы — 443 или 80 (ревью Codex и замер, «Найдено по ходу»).
* **База:** наружу не открыта; пароли — из `.env`. Пароль роли `selfin_app` ставит само приложение после миграций: обратный вызов Flyway `afterMigrate` выполняет `ALTER ROLE selfin_app PASSWORD …` ролью миграций, пароль — из `selfin.db.app-password` (`SELFIN_DB_APP_PASSWORD`), в кавычки его ставит Postgres (`format('%L')`). Ручного шага на сервере нет, и забыть его нельзя.
* **Перезапуск:** у всех контейнеров `restart: unless-stopped`. nginx фронта ищет бэк по имени на каждый запрос (`resolver` Docker и адрес в переменной) — стартует и без бэка, а бэк, поднявшийся позже, находит сам. Это лечит и стенд: «фронт поднимать после бэка» больше не нужно.
* **Память:** лимиты контейнеров JVM — по замеру на машине стенда (раздел «Выполнено»).

### Найдено по ходу

* **Caddy: `respond` срабатывает позже `handle`.** В первой редакции `Caddyfile` реалм `master` и консоль учётной записи отвечали 200 — закрытие не работало, а `/auth/admin/` закрыл сам Keycloak: при `KC_HOSTNAME_ADMIN` он не отдаёт консоль по публичному адресу. Теперь `route` — директивы строго по порядку записи; живая проверка — та же таблица.
* **nginx передавал схему без порта.** Tomcat, получив `X-Forwarded-Proto` без `X-Forwarded-Port`, ставит порт схемы. На 8443 адрес возврата терял порт — в первой редакции это записано как «публичный адрес — только на 443». Codex указал, что шаблон `.env` сам предлагает другие порты. Замер нашёл то же и на стенде: nginx шлёт `http` и там, адрес возврата выходил без 5174, и вход на стенде сломался бы с первой же пересборкой фронта. Теперь порт берётся из `Host` — таблица выше.
* **Выход всех на вход после выкладки** — решено 15.10 в ANO-152, вопроса нет (раздел «Что было»).
* **Консоль учётной записи для шага 7.** При `KC_HOSTNAME` на публичный адрес Keycloak строит переходы консоли учётной записи от него, и SSH-туннель к ней не годится. Для одного входа владельца в шаге 7 — временно открыть её маршрут в `Caddyfile` или найти другой путь; решить в шаге 7.

### Тесты и мутации

`ServerSetupIT` — 4 теста: пароль роли из настройки, за прокси — `https` и `Secure`, за прокси на своём порту — порт из `X-Forwarded-Port`, без прокси — как было. Весь бэк до правки порта — 497 юнитов и 351 IT, всё зелёное; после неё `ServerSetupIT` — 4 из 4. Сторож реалма — 12 из 12, сторож nginx — 5 из 5. Тест порта в `ServerSetupIT` зелёный сразу: порт из заголовка Tomcat читает сам, правка — в nginx, и красным до неё был сторож nginx.

| мутация | что | итог |
|---|---|---|
| R1, R2 | в реалме нет адреса сервера — возврата, выхода | красные — сторож реалма |
| G3, G4 | nginx не передаёт схему; без прокси схема пустая | красные — «схема запроса» |
| G5, G6 | без `resolver`; адрес бэка прямо в `proxy_pass` | красные — «бэк ищется по имени» |
| J1 | нет `server.forward-headers-strategy` | красная — `ServerSetupIT.behindHttpsProxy` |
| J2 | обратный вызов не срабатывает | красная — `password authentication failed for user "selfin_app"` |
| G7, G8 | порт из `Host` не берётся; nginx не передаёт порт | красные — «публичный порт» |
| J3 | Tomcat читает порт из другого заголовка (`server.tomcat.remoteip.port-header`) | красная — `ServerSetupIT.behindHttpsProxyOnOwnPort` |
