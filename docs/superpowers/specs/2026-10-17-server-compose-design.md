## Как

**Папка `deploy/`** — всё, что нужно серверу кроме образов: `docker-compose.yml`, `Caddyfile`, `.env.example`. На сервере — клон репозитория (он открытый), `cd deploy`, `.env` по шаблону, `docker compose pull && docker compose up -d`. Реалм берётся из `../keycloak/selfin-realm.json` того же клона.

* **Caddy впереди** — сам получает и продлевает сертификат Let's Encrypt для `SELFIN_DOMAIN`, проставляет `X-Forwarded-Proto`. Порты 80 и 443 — переменными: если у друга они заняты его сайтом, встаём за его прокси (решить в шаге 6 по ответу друга).
* **Один адрес:** приложение — на `/`, Keycloak — под `/auth` (`KC_HTTP_RELATIVE_PATH`). Снаружи закрыты: консоль администратора (`/auth/admin`), реалм `master` и консоль учётной записи (`/auth/realms/selfin/account`) — через неё учётная запись заводится мимо согласия (шаг 4).
* **Консоль администратора — с самого сервера:** Keycloak слушает `127.0.0.1:8180` машины, `KC_HOSTNAME_ADMIN` — этот адрес; с компьютера владельца — SSH-туннель. Туда же ходят команды `tools/` (`SELFIN_KC_ADMIN`).
* **Keycloak в боевом режиме:** `start --import-realm`, `KC_HOSTNAME` — публичный адрес с `/auth`, `KC_PROXY_HEADERS=xforwarded`, `KC_HTTP_ENABLED=true` за прокси, пароль администратора — из `.env`; своя база отдельным контейнером.
* **Реалм как код:** к адресам стенда добавлены `${SELFIN_PUBLIC_URL:…}/login/oauth2/code/keycloak` и `${SELFIN_PUBLIC_URL:…}/login`: на сервере — его адрес, на стенде без переменной — адрес стенда. Подстановку делает импорт реалма при первом старте Keycloak.
* **Сервер за HTTPS-прокси:** `server.forward-headers-strategy=native` — Tomcat верит `X-Forwarded-Proto` от внутренних адресов (сеть Docker); nginx фронта передаёт схему прокси, а без прокси — свою (`map`). Тогда адрес возврата из Keycloak — `https://…`, а cookie сеанса — `Secure`.
* **База:** наружу не открыта; пароли — из `.env`. Пароль роли `selfin_app` ставит само приложение после миграций: обратный вызов Flyway `afterMigrate` выполняет `ALTER ROLE selfin_app PASSWORD …` ролью миграций, пароль — из `selfin.db.app-password` (`SELFIN_DB_APP_PASSWORD`), в кавычки его ставит Postgres (`format('%L')`). Ручного шага на сервере нет, и забыть его нельзя.
* **Перезапуск:** у всех контейнеров `restart: unless-stopped`. nginx фронта ищет бэк по имени на каждый запрос (`resolver` Docker и адрес в переменной) — стартует и без бэка, а бэк, поднявшийся позже, находит сам. Это лечит и стенд: «фронт поднимать после бэка» больше не нужно.
* **Память:** лимиты контейнеров JVM — по замеру на машине стенда (раздел «Выполнено»).

## План

1. Тесты красные до правки: сторож реалма — адресов сервера нет; сторож nginx — нет передачи схемы и `resolver`; IT за прокси — адрес возврата `http`, cookie без `Secure`; IT пароля роли — приложение со своим паролем не стартует.
2. Код и файлы: `deploy/`, `nginx.conf`, `application.properties`, обратный вызов Flyway, реалм, необязательный адрес Admin API в `tools/keycloak-check.mjs`.
3. Мутации на итоговом коде.
4. Машина стенда: серверная сборка отдельным проектом — `https://localhost:8443`, консоль администратора на `127.0.0.1:8190`; проверки — раздел «Как мерил».

## Как мерил

Машина стенда, серверная сборка отдельным проектом `selfin-server` с образами из ветки: `SELFIN_DOMAIN=localhost`, `SELFIN_PUBLIC_URL=https://localhost:8443`, Caddy — на портах 8088 и 8443 (сертификат его внутреннего центра), консоль администратора — `127.0.0.1:8190`.
