## 1. Где мы на маршруте

```
а) чиним критичное                ← закрыт по взятому списку: 10 PR, 18 задач
б) фиксируем состояние,           ← первая половина закрыта, вторая — с этого спринта
   доводим до пригодного к показу
в) многопользовательская часть    ← ждёт решения ANO-143
г) выкладываем на сервер
д) всё остальное
```

Ретро пометило «б» закрытым, но по дороге формулировка сузилась. В исходной (`2026-09-11-two-prompts.md:47`) у «б» две половины. Первая сделана: состояние зафиксировано — ручной проход ANO-50, карта бэклога, ноль открытых PR. Вторая, «довести до пригодного к показу», не начиналась: из 49 задач, которые карта бэклога отнесла к «б», закрыты две (ANO-119, ANO-122).

Владелец 23.09: «согласен с предложением им и заняться, довести его до конца».

**Почему не «в» сразу.** «В» не может стартовать без решения о способе входа (ANO-143 блокирует весь эпик). Список категорий станет шаблоном каждого нового пользователя (ANO-151) — сначала список, потом шаблон. Миграция «в» (владелец в 11 таблиц) — самая рискованная в проекте, и CI с прогоном миграций должен появиться раньше неё.

## 6. Где у «б» конец — принято владельцем 23.09.2026

Закрыть «б» списком — это около семидесяти задач, то есть несколько спринтов, и часть из них к показу отношения не имеет: «календарь как основной вид» (ANO-65), архитектурная правка траекторий (ANO-23).

Предлагается черта по смыслу, а не по списку: **«б» закончен, когда посторонний проходит этап A** чек-листа `2026-08-30-manual-test-checklist.md`:

* **A1** — ответ читается без объяснений, за пять минут, без подсказок;
* **A2** — ответ есть на неполных и устаревших данных;
* **A3** — ре-якорь ощущается как «несколько цифр раз в месяц»;
* **A4** — объяснение числа читается предложениями, а не формулой.

5 сентября этап провалился на A1 и A4. С тех пор дашборд перестроен (ANO-119), так что A1, возможно, уже проходит — это замер, а не догадка, и стоит он один сеанс с посторонним.

| вариант | что значит | цена |
|---|---|---|
| по списку | закрыть все ~70 | несколько спринтов; «в» и живые люди сдвигаются на столько же |
| по черте | закрыть то, что мешает этапу A, плюс открытые High; остальное — в «д» | черту проверяет посторонний, а не владелец, — нужен человек на один сеанс |

**Принято по черте.** Владелец 23.09: «Черту ты сам правильно провёл, я согласен».

Следствия: «б» закрывается прогоном этапа A с посторонним, а не числом закрытых задач. Задачи «б», которые не мешают этапу A и не несут High, уходят в «д» — разбор, какие именно, делается перед прогоном, по результатам первого сеанса. Первый сеанс нужен и как замер: после ANO-119 A1 мог уже пройти. Задача — ANO-179.

## 7. Как проверяется готовность задачи в этом спринте

Цикл прежний: разбор inline → спека (с планом в одном документе, если шагов немного) → TDD → мутации → стенд → PR → Linear.

Новое с этого спринта, по разделу 9 ретро:

* локально гоняется только затронутое; полный набор — дело CI;
* готовый дифф — сигнал владельцу на `/code-review`;
* для CI мутационная проверка означает: каждая проверка хотя бы раз показана красной на подсаженной поломке.

**Способ работы, поправлен 24.09.**

* Сам вливаю только механическое — CI, сторожа, тесты, доки без выводов — после ответов Codex.
* Вывод или продуктовое решение сначала разбирается с владельцем в чате, по вопросу за раз.
* Готовый дифф — сигнал владельцу; вливание — после его «ок».
* Задача не закрывается, пока владелец не видел вывод.
* Макет варианта — файлом, артефактом или снимком стенда. Встроенные виджеты в чате у владельца не отрисовываются: 24.09 он выбирал вариант ANO-100 по описанию.
* Снимок стенда для владельца — безголовым Edge (`msedge --headless=new --screenshot --window-size=500,760 --virtual-time-budget=8000`); уже 500 px он не раскладывает. Когда нужны нажатия и прокрутка — тот же Edge через CDP (`--remote-debugging-port`), Node 22 умеет WebSocket без пакетов.
* **Объяснения — в справку продукта** (владелец 25.09). Новое понятие или режим на экране — сразу вопрос, где человек прочтёт, что это; текст справки входит в ту же задачу.
* **Номер задачи в заголовке PR закрывает её при вливании.** В заголовок — только задачи, которые этот PR закрывает; остальные — в описание.
* **Корень числа на экране — от экрана к формуле.** 25.09 оказалось, что комментарий в ANO-88 от 23.09 назвал корнем `FundPlannerService`, а экран его не вызывает. Шестой случай «узкая проверка — широкий вывод».
* **Перед переключением ветки — закоммитить.** 25.09 незакоммиченные правки ANO-140 переехали вместе с переключением на ветку #73; разделил через stash, прогоны перезапустил.
* **Цикл без пропусков — указание владельца 26.09:** «не забывай про анализ, про соотношение продуктовым правилам, тесты, проверки»; мнение владельца по ходу можно не спрашивать, если решение обосновано анализом. В каждой спеке — раздел «Правила продукта — сверка» по каждому правилу канона; мутации — на итоговом коде; полный прогон юнитов, а не только точечный. Первая же сверка задним числом нашла в #75 три дефекта.
* **Сигнал «ждёт ок» — после ответа Codex, а не после открытия PR.** Codex ставит 👀, затем замечания или 👍. На #75 и #76 замечания пришли минут через десять после открытия и провисели без ответа до следующей сессии.

## 9. Куда легли новые задачи — без сеанса с посторонним

Первый сеанс с посторонним должен был рассортировать остаток «б» (раздел 6). Человека нет. Поэтому владелец 24.09 принял правило: **что дёшево и лежит на пути постороннего по первому экрану — в «б»; остальное — после черты.**

**Решение владельца 25.09, вечер: «к бэку пока что».** После ANO-77 очередь «б» по первому экрану предлагала ANO-120 (навигация на телефоне), остаток ANO-76 (слово «кармашек»), ANO-123 (упрёки) и ANO-99 (фраза повторяет число).
