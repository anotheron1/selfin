# «Структура месяца» — только числа (ANO-165, ANO-161)

Блок B спринта 26.09, задачи B4 и C5 — одним PR, решение владельца 28.09. Вариант А владельца: по каждому характеру факт и план числами, без приговоров, процентов и счётчика; карточка хотелок уходит вместе со своей выборкой.

## Что сломано

Замер 28.09 на стенде `26464f4`, сентябрь; раздел «Как мерил». «Аналитика» → «Как прошёл месяц» → «посмотреть» → «Структура месяца»:

```
Брони       0 ₽ / 61 600 ₽                сэкономил 61 600 ₽
Ожидания    5 000 ₽ · 500000% бюджета      Перерасход: 5 000 ₽
            брони 0% · ожидания 500000% · хотелки 0%
Хотелки     0 из 5 выполнена               выполнена · в плане · в списке
```

`priorityBreakdown` ответа `/analytics/report`: брони — факт 0 из плана 61 600, ожидания — 5 000 из 20 500, хотелки — 0 из 77 004, доход по факту — 0.

* **«% бюджета»** — доля от дохода месяца по факту. Дохода пока нет, и делитель подменён на 1 (`total = totalIncomeFact > 0 ? … : 1`): 5 000 ₽ — это «500000%». «Перерасход: 5 000 ₽» — траты больше полученного дохода. Язык запрета 1, число — мусор.
* **«сэкономил 61 600 ₽»** — факта по броням 0: они не оплачены, семь уже с прошедшей датой (в кармашке — «Брони с прошедшей датой (7 шт)»). Приговор задним числом, и неверный — правило 12.
* **«0 из 5 выполнена»** — счётчик несделанного (правило 12). И считает он не хотелки: `GET /events/wishlist` (`findWishlistItems` — «Хотелка» по характеру, план, без факта, дата пустая или раньше начала месяца) отдаёт на стенде пять обычных строк характера «Хотелка» из прошлых месяцев — «Бассейн» 21.03, «Перевод на счет» 30.04, «Бассейн» 21.05, «OCR» 21.08, «Бассейн Арсу» 26.08. Ни одной с экрана «Хотелки»: у тех срок — этот месяц или позже. Хотелки без срока попали бы — любого статуса, как описано в ANO-161.

Замысел блока (спека `2026-04-09-technical-debt-and-ux-design.md`, до канона) — три вопроса: «обязательства покрыты?», «какую долю занимают в бюджете?», «сколько желаний реализовано?». Все три подачи — приговоры или бюджет. Блок стоит под «посмотреть» — по запросу, запрет 2 соблюдён (ANO-119).

## Решение

* **Блок — только числа.** По каждому характеру строка «{имя}: {факт} из {план}»: «Брони: 0 ₽ из 61 600 ₽», «Ожидания: 5 000 ₽ из 20 500 ₽», «Хотелки: 0 ₽ из 77 004 ₽». Имена и цвет точки — из `lib/priority.ts`. Под заголовком строка объяснения: «Сколько потрачено по каждому характеру и сколько на него запланировано в этом месяце». Строки считает одна функция — `monthStructureRows(breakdown)` в `lib/monthStructure.ts`.
* **Уходят:** «сэкономил», «перерасход», проценты, «бюджет», полоса долей, карточка хотелок с точками и счётчиком.
* **Уходит выборка карточки** — единственный потребитель `GET /events/wishlist`: ручка, `FinancialEventService.findWishlist`, `FinancialEventRepository.findWishlistItems`, клиентская `fetchWishlist`, её юнит, строка в `tools/ci-migrations.sh`, запись в контракте. Второго, неверного списка хотелок больше нет. `POST /events/wishlist` — заведение хотелки — остаётся.
* **Долги сторожа словаря** за ANO-165 — четыре строки `productRules.test.ts` — вычёркиваются: нарушений больше нет.
* `priorityBreakdown.totalIncomeFact` в ответе остаётся: поле контракта, убирать — отдельная правка без пользы для экрана.
