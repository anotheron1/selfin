# Экран входа, выход через Keycloak, сеанс (ANO-152)

Шаг 11 спринта 5 (`2026-10-11-sprint-5-plan.md`, раздел 3). Спека и план — одним документом. Факультатив — блок 5, вне git: раздел 1 (CORS) уже написан с ANO-153, здесь — остальное.

Решения владельца 15.10:

* **«Выйти» и кто вошёл — внизу экрана «Настройки»**, нижнюю навигацию не трогаем (ANO-120);
* **кнопка «Войти через Telegram» сразу ведёт к подтверждению в Telegram** — `kc_idp_hint`, страница Keycloak не показывается;
* **длина сеанса** — ждёт ответа (раздел «Сеанс»).

Решено раньше: Р-1 = Б — токенов во фронте нет; выход завершается и в Keycloak (ревью Codex на #147); ключ песочницы — по человеку; Яндекс ID и VK ID — неактивными кнопками.

## Что есть сейчас

* **Входа на экране нет.** Любой запрос API без сеанса — 401, и `client.ts` уводит браузер прямо на `/oauth2/authorization/keycloak` → страница Keycloak «Вход Selfin»: форма логина с паролем (паролей в реалме нет) и кнопка Telegram; «or» и «Sign in with Telegram» — по-английски (замер 14.10 в ANO-152).
* **Выхода нет вовсе** — ни кнопки, ни настройки на сервере. `POST /logout` Spring по умолчанию гасит только наш сеанс; сеанс Keycloak жив, и «Войти» впустит снова без подтверждения в Telegram.
* **Регистрация клиента — свойствами, без discovery** (`application.properties`): у неё нет ни `end_session_endpoint`, ни издателя. Выход через Keycloak не собрать, `iss` у ID token не сверяется (спека 13.10, «Два адреса Keycloak»).
* **CSRF — `spa()`: форма выхода с токеном из cookie получит 403.** `CsrfConfigurer$SpaCsrfTokenRequestHandler` (байткод Spring Security 7.0.3): есть заголовок `X-XSRF-TOKEN` — токен сверяется как есть; нет — параметр `_csrf` разбирается как замаскированный (XOR). У фронта только сырой токен из cookie. План 12.10 «`POST /logout` формой» в нашей настройке не работает.
* **Сеансы:** наш — 30 минут без действий, в памяти (по умолчанию Tomcat); Keycloak — 30 минут без действий и не дольше 10 часов, «запомнить меня» выключено (замер на стенде, Admin API).
* **`GET /api/v1/me`** — только `id`.
* **Песочница** хранит черновик под одним ключом `selfin.sandbox.v1` на браузер: двое на одном браузере увидят примерку друг друга.
* **Живая проверка входа** (`tools/keycloak-check.mjs`) входит тестовым человеком через форму Keycloak — паролем.

## Решение

### 1. Свой экран входа `/login`

Маршрут SPA: название, **«Войти через Telegram»**, ниже неактивные **«Яндекс ID»** и **«VK ID»** с пометкой «скоро» и строка «Selfin получит из Telegram только имя и ник — без телефона» (в реалме у провайдера — `openid profile`, без телефона, ANO-143). Нижней навигации и «+» на экране нет. Прокси nginx и Vite отдают `/login` фронту — на бэк уходят только `/login/oauth2/…`.

### 2. На 401 — на наш экран

`client.ts` на 401 уводит на `/login`, а не прямо в Keycloak.

### 3. Кнопка — сразу в Telegram: `kc_idp_hint` по запросу экрана

Кнопка ведёт на `/oauth2/authorization/keycloak?provider=telegram`. Сервер (резолвер запроса авторизации) переносит `provider` в `kc_idp_hint` — только известные значения; сейчас это `telegram`. Keycloak со подсказкой своей страницы не показывает и сразу уводит к Telegram.

Подсказка — по запросу, а не на каждый вход: живая проверка стенда и тестовый человек входят формой Keycloak, а с подсказкой на всё форма пропала бы. Будущие Яндекс и VK — та же схема, своё значение у каждой кнопки.

### 4. Выход: «Выйти» в «Настройках» — через наш сервер и Keycloak

Внизу «Настроек» — «Вы вошли как {имя}» и **«Выйти»**. Нажатие:

1. `fetch` `POST /logout` с заголовком `X-XSRF-TOKEN` — CSRF проходит;
2. сервер гасит наш сеанс и отвечает **200 с адресом выхода Keycloak** — `end_session_endpoint` с `id_token_hint` и `post_logout_redirect_uri = {адрес экрана}/login` (`OidcClientInitiatedLogoutSuccessHandler`, ответ JSON вместо 302);
3. экран переходит по адресу — браузер проходит выход Keycloak, сеанс Keycloak погашен;
4. Keycloak возвращает на `/login`.

Переход по адресу делает браузер — то, ради чего 12.10 выбиралась форма; форма же с CSRF `spa()` не проходит (раздел «Что есть сейчас»).

### 5. Регистрация клиента — в коде

`ClientRegistrationRepository` — из свойств Boot (`OAuth2ClientPropertiesMapper`) плюс `end_session_endpoint` и издатель `issuerUri` — адрес реалма для браузера. Издатель включает сверку `iss` у ID token — обещание спеки 13.10. Свойства и адреса Keycloak остаются где были.

### 6. Кто вошёл — `GET /api/v1/me` с именем

`{"id": …, "name": …}`: у сеанса браузера — `name` из ID token (Telegram присылает «Имя Фамилия»), иначе `preferred_username` — ник; у Bearer — те же утверждения из JWT.

### 7. Реалм: куда возвращаться после выхода

У клиента `selfin` — `post.logout.redirect.uris`: `/login` на тех же четырёх адресах экрана, что и адреса возврата входа. Реалм стенда импортирован один раз — правка на стенд Admin API, реалм не пересоздаётся (пересоздание снесло бы учётную запись владельца, связанную с Telegram).

### 8. Песочница — по человеку

Ключ — `selfin.sandbox.v1.{id из /me}`. Пока id не известен, черновик не читается и не пишется. Общий ключ `selfin.sandbox.v1` при первом чтении стирается: чей он — не узнать, а отдать чужому — та самая утечка.

### 9. Сеанс

Ждёт решения владельца: А — как сейчас, 30 минут и 10 часов; Б — 30 дней без действий; В — 7 дней. От ответа зависит только настройка: `server.servlet.session.timeout` и сеанс реалма (`ssoSessionIdleTimeout`, `ssoSessionMaxLifespan`). Сеанс сервера остаётся в памяти: после перезапуска — один клик «Войти» без подтверждения, пока жив сеанс Keycloak.

## Как проверяется

| что | проверка | мутация |
|---|---|---|
| кнопка — сразу в Telegram | `SignInIT`: вход с `provider=telegram` несёт `kc_idp_hint=telegram`, без него — нет; PKCE S256 — как прежде | `provider` не переносится |
| неизвестный `provider` не уходит в Keycloak | `SignInIT`: `provider=evil` — без подсказки | без проверки значения |
| выход гасит оба сеанса | `SignInIT`: `POST /logout` с CSRF — 200 и адрес выхода Keycloak с `id_token_hint` и `post_logout_redirect_uri=…/login`; следующий запрос — 401 | обычный ответ 302; без `end_session_endpoint` |
| кто вошёл | `SignInIT`: `/me` — имя из ID token и из Bearer | — |
| 401 — на наш экран | `client.test.ts` | уход прямо в Keycloak |
| выход с экрана | тест помощника выхода: `POST /logout` с заголовком CSRF и переход по адресу из ответа | без заголовка |
| песочница своя | `sandboxStorage.test.ts`: черновик одного не читается другим, общий ключ стирается | общий ключ |
| реалм | сторож реалма и `keycloak-check.mjs`: адреса после выхода на месте; вход по кнопке уходит к Telegram сразу | — |

Стенд: экран `/login` и вход тестовым человеком формой Keycloak — как прежде; кнопка — сразу к `oauth.telegram.org`; выход — через Keycloak на `/login`, и следующий вход формой снова спрашивает пароль: сеанс Keycloak погашен. Вход через Telegram до конца — владельцем.

## План

1. Тесты бэка — `SignInIT`: подсказка, выход, `/me`. Красные.
2. Регистрация в коде, резолвер подсказки, обработчик выхода, имя в `/me` — зелёные.
3. Реалм: адреса после выхода; сторож и `keycloak-check`.
4. Фронт: экран `/login`, 401 → `/login`, «Выйти» в «Настройках», песочница по человеку; тесты — красные, затем зелёные.
5. Сеанс — по ответу владельца.
6. Полный прогон, мутации на итоговом коде.
7. Стенд до и после: реалм Admin API, образы фронта и бэка из ветки.
8. PR, блок 5.

## Не входит

* **Яндекс ID, VK ID** — неактивные кнопки; провайдеры — после Telegram.
* **Тема Keycloak** — его страница с подсказкой не показывается; переводы темы — если понадобится, отдельно.
* **Сеанс в базе** (Spring Session JDBC) — сеанс сервера в памяти; при долгом сеансе Keycloak перезапуск стоит один клик.
* **Кого пускать на сервер** — ANO-197.

## Как мерил

* **Вход и выход сейчас** — код: `frontend/src/api/client.ts` (401 → `/oauth2/authorization/keycloak`), `SecurityConfig` (настройки выхода нет), `application.properties` (регистрация без discovery), `MeController`; экран — замер 14.10 в ANO-152.
* **CSRF и форма** — `javap -c` класса `CsrfConfigurer$SpaCsrfTokenRequestHandler` из `spring-security-config-7.0.3.jar`.
* **Сеансы** — `application.properties` (длина не задана), реалм стенда через Admin API: `ssoSessionIdleTimeout` 1 800 с, `ssoSessionMaxLifespan` 36 000 с, `rememberMe` false.
* **Регистрация в коде** — `javap` `OAuth2ClientPropertiesMapper` (публичный, `asClientRegistrations()`) и `OAuth2ClientConfigurations$ClientRegistrationRepositoryConfiguration` (`@ConditionalOnMissingBean`) из `spring-boot-security-oauth2-client-4.0.3.jar`.
* **Что Telegram присылает** — блок 2 факультатива: `name`, `preferred_username`, без телефона.
* **Прокси** — `frontend/nginx.conf`, `frontend/vite.config.ts`: `/login` не проксируется.
