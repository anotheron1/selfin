# Фиксация кредита ставит платежи на ту же копилку; «Что с капиталом» — платёж один раз (Р2: ANO-40, ANO-190)

PR 2 спринта 4 (`2026-10-03-sprint-4-plan.md`, раздел 3). Решения владельца: карта C1 (`2026-10-03-money-answers-map-design.md`), Р2, вариант 2 — 03.10; уточнение 05.10 в чате — вариант Б: график на ту же копилку, в примерке и в диалоге. Спека и план одним документом.

## Что на экране

* **ANO-40.** «Зафиксировать» в примерке меняет статус и параметры, а в плане ничего: «Стратегия» не двигается ни на рубль. Ядро держит взносы только у копилок-накоплений (`PocketInputAssembler`, шаг 2а).
* **Две кнопки делают разное.** Диалог «Что с капиталом» ставит 12 броней, но заводит вторую копилку с тем же именем — на «Целях» две «Проверки кредита». Так сейчас и у «цукцку»: исходная сконвертирована в новую копилку с тем же именем.
* **ANO-190.** «Что с капиталом» после диалога на декабрь — 132 264,30 при «Стратегии» 22 926,15. Ядро держит бронь декабря, а дельта новой копилки — формула `computeCreditDelta`: «+120 000 на счёт» в месяц покупки и платёж ещё раз. Копилки-кредита нет в `baselineRefs`, поэтому основа без зафиксированного её платежи не возвращает, а блок накладывает формулу сверху.
* **Найдено по ходу.** «Вернуть в обсуждение» с удалением созданного убирает копилку, а 12 броней остаются: «Свободно» и «Стратегия» держат платежи кредита, от которого отказались. `WishlistArtifactService.deleteFund` помечает копилку удалённой и правило платежей не трогает; удаление копилки на «Целях» — тоже.
* **«Свободно» на 3 месяца** все шаги — −190 312: это минимум на 12.10, платежи — с декабря.

## Решение

**Р2-Б — график платежей на ту же копилку.**

* **«Зафиксировать» у кредита** — и в примерке, и пункт «Кредит» диалога «Что с капиталом» с галочкой «Создать график платежей» — ставит график бронью на эту же копилку. Новая копилка не заводится, на «Целях» карточка одна. Платёж — аннуитет по ставке и сроку, первый — в месяц после покупки, тем же днём (как правило конверсии сейчас).
* **Без ставки или срока** — 400 до любой записи, как в диалоге сейчас.
* **«Вернуть в обсуждение», «Отложить» и удаление копилки-кредита** снимают её будущие платежи тем же путём, что «эту и следующие» в журнале (`RecurringRuleService.deleteScope`, FOLLOWING от первого платежа с сегодняшнего дня). Прошедшие и исполненные остаются: это история. Так же — удаление созданного у старых копий из прошлых конверсий.
* **Повторная фиксация** — после возврата в обсуждение графика уже нет; если он остался, сначала снимается, потом ставится заново: двух графиков у копилки не бывает.
* **Платежи графика — то, что ядро держит по ссылке копилки-кредита** (`baselineRefs`, шаг 2б). Примерка: зафиксированный кредит «в основе», выключить — исключить его платежи. «Что с капиталом»: основа без зафиксированного возвращает их, дельта кредита по оси счёта — ровно они, без «+сумма на счёт» в месяц покупки; ось капитала и долга — прежняя формула. При открытии блок равен «Стратегии».
* **Опознание графика — по правилу**, как миграция V27: правило, у которого хоть одно событие — живое или удалённое — ссылается на копилку-кредит. Ссылку несут события, а правка правила перегенерирует их без неё.
* **Подпись в диалоге:** «Кредит (копилка + график платежей)» → «Кредит (график платежей)»: копилка больше не заводится.

## Не закрывает

* **«Зафиксировать без конверсии»** у кредита в диалоге и снятая галочка «Создать график платежей» — статус без графика, как было. Блок такого кредита — по формуле, со «+сумма на счёт»: он не равен «Стратегии», но это явный выбор человека.
* **Старые копии** из прошлых конверсий копилок («цукцку») — две карточки остаются; путь «Копилка» диалога по-прежнему заводит копию. Отдельная задача — раздел «Нашлось по ходу».
* **Формула кредита у обсуждаемого** (примерка «а если»): «+сумма на счёт» в месяц покупки — как была.
* **Будущий платёж с частичным фактом** при снятии графика: план с фактом остаётся, если он уже исполнен (`EXECUTED`); частичный факт по будущему платежу — редкий случай, путь журнала тот же.

## Ревью Codex на #138

* **P1 — график ищется только у копилки-кредита.** Журнал передаёт копилку в правило при любом типе: через API можно завести расход-правило со ссылкой на копилку-накопление. Снятие «графика» при её удалении или смене статуса уничтожало чужую серию — тест `savingsFundLinkedRule_isNotACreditSchedule`: 6 событий → 0. Теперь правила графика — только у копилки-кредита, как опознаёт V27 (`findCreditPaymentRuleIds`). Отдельный признак правила в базе не заводим: переводов правилом не бывает (V16), а связь «правило — копилка-кредит» уже служит признаком. Поправлено в `c2d8b10`.
* **P2 — «Кредит» для копилки-накопления делает её кредитом.** Диалог принимает пункт «Кредит» и у копилки-накопления со ставкой и сроком; копия раньше заводилась кредитом (`buildCreditFund`), на месте график ставился, а вид оставался SAVINGS, и ядро его не опознавало. Теперь вид меняется на месте — тест `convert_savingsWithCreditParams_becomesCredit`. Поправлено в `c2d8b10`.
* Мутации: без ограничения «только кредит» — красный `savingsFundLinkedRule_isNotACreditSchedule`; без смены вида — красный `convert_savingsWithCreditParams_becomesCredit`.
* **Второй круг, P1 — смена вида кредита.** Редактор копилок разрешает сменить вид кредита на накопление (`TargetFundService.update`); после этого график уже не опознать, и при отказе платежи оставались бы. Теперь `update` снимает график до смены вида — тест `creditToSavings_unschedulesBeforeTypeChange`. Поправлено в `df0bc6c`.
* **Второй круг, P2 — платёж с датой сегодня.** Ядро держит его (`todayPending`), а по ссылке кредита он не шёл: исключение кредита в примерке оставляло сегодняшний платёж, основа блока не возвращала его в текущий месяц. Платежи кредита — с сегодняшнего дня, как у ядра; хотелки — как были, после сегодня. Тест `sandbox_excludeCredit_removesTodaysPayment`. Поправлено в `df0bc6c`.
* Мутации второго круга: без снятия в `update` — красный `creditToSavings_*`; платежи снова «после сегодня» — красный `sandbox_excludeCredit_*`.
* **Третий круг, P1 — расход-серия у копилки-накопления, ставшей кредитом.** Продолжение первого P1: если такая серия уже есть, пункт «Кредит» меняет вид копилки до поиска графика — и серия снялась бы вместе с ним, а без галочки считалась бы платежами кредита. Корень — вход журнала: `POST` и `PUT /events` принимали копилку у события любого типа, хотя экран шлёт её только переводу, а переводов серией не бывает (V16). Других входов у ссылки нет — правило с копилкой заводят только журнал и график кредита. Теперь журнал отвечает 400 на копилку у расхода и дохода — тесты `journal_rejectsFundLinkOnNonTransfer`, `journalUpdate_rejectsFundLinkOnNonTransfer`; мутации — без проверки в `createIdempotent` и в `update`, обе красные своим тестом. Признак правила в базе по-прежнему не заводим. Поправлено в `f4d9029`.
* Слияние `main` с #135 дало смысловой конфликт без текстового: #135 завёл в `TargetFundAccountTest` второй конструктор сервиса (`serviceOn`) без новой зависимости `CreditPaymentService` — компиляция тестов падала. Поправлено в `751fce8`. Прогон после слияния: бэк — 491 юнит и 283 IT, фронт — 519.
* **Не закрывает:** правка суммы, срока или ставки зафиксированного кредита в редакторе копилок не переставляет график — платежи остаются по прежним параметрам. Путь Р2-Б — вернуть в обсуждение, поправить в примерке, зафиксировать.

// PR 2 (Р2): замер «до» на стенде через API продукта. node scenario.mjs
// Тестовый кредит из ANO-190: 120 000 под 12% на 12 месяцев, покупка 10.11, первый платёж — декабрь.
import { randomUUID } from 'node:crypto';

const API = 'http://localhost:8081/api/v1';
const NAME = 'Проверка кредита';
const DEC = '2026-12';

async function call(method, path, body) {
  const r = await fetch(API + path, {
    method, headers: { 'Content-Type': 'application/json', 'Idempotency-Key': randomUUID() },
    body: body ? JSON.stringify(body) : undefined,
  });
  const text = await r.text();
  if (!r.ok) throw new Error(`${method} ${path} → ${r.status} ${text}`);

/** «Что с капиталом» при открытии: основа + накопленные дельты включённых (зафиксированных) — как composeTimeline. */
function blockAt(sim, ym) {
  // Как useWishlistSimulation: дельты ложатся на точки FUTURE, индекс 0 — следующий месяц.
  const future = sim.baseline.points.filter(p => p.phase === 'FUTURE');
  const idx = future.findIndex(p => p.yearMonth === ym);
  let v = future[idx].balance;
  for (const it of sim.items) {
    if (it.status !== 'FIXED') continue;
    for (const d of it.delta) if (d.monthIndex <= idx) v += d.accountDelta;
  }
  return Math.round(v * 100) / 100;
}
