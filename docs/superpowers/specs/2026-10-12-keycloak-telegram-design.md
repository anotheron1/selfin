# Keycloak и вход через Telegram (ANO-143)

Шаг 1 спринта 5 (`2026-10-11-sprint-5-plan.md`, раздел 3). Решения владельца 11.10: Keycloak — потому что рыночный стандарт; первым — Telegram. Спека и план одним документом. Факультатив — блоки 1 и 2, вне git.

## Что есть сейчас

* **Входа нет.** Все 63 ручки открыты, фронт ходит в `/api/v1` без токена, человек один — владелец.
* **У Telegram — стандартный OpenID Connect** ([документация](https://core.telegram.org/bots/telegram-login), прочитана 12.10): discovery `https://oauth.telegram.org/.well-known/openid-configuration`, `/auth`, `/token`, JWKS. Код с PKCE S256; секрет на `/token` — по Basic. Области: `openid` — `sub`, `iss`, `iat`, `exp`; `profile` — `id`, `name`, `preferred_username`, `picture`; `phone` — номер, с согласия человека; `telegram:bot_access` — бот сможет писать человеку. Отдельного userinfo нет. ID token подписан RS256, `aud` — ID бота, живёт час.
* **Адреса возврата — только заранее записанные** в @BotFather: бот → Login Widget → Allowed URLs; там же Client ID и Client Secret. Про `localhost` и `http` документация молчит, все примеры — HTTPS. Принимает ли бот наш адрес — первая проверка задачи, у владельца.

## Решение

* **Keycloak 26.8.0** — последний выпуск на 12.10 (вышел 01.10.2026), закреплён тегом образа. Режим `start-dev`: стенд локальный, по HTTP. `start` с HTTPS и доменом — «Выкладка».
* **Только на стенде** — `docker-compose.test.yml`, порт 8180. Экземпляру владельца (`docker-compose.yml`) Keycloak не нужен до ANO-195 — там он и появится.
* **Своя база — отдельным контейнером `keycloak-db`**, а не отдельной базой в нашем Postgres, как предлагал план. Init-скрипты образа Postgres работают только на пустом томе, а тома стенда и владельца уже есть: базу пришлось бы заводить отдельным шагом. Отдельный контейнер заводится сам, а его обновления и сброс не задевают нашу базу и её дампы.
* **Реалм `selfin` как код** — `keycloak/selfin-realm.json`, импорт при первом старте (`--import-realm`). Если реалм уже есть, Keycloak импорт пропускает. Пересоздать — команда в шапке `docker-compose.test.yml`: убрать Keycloak и его том, поднять заново; люди, вошедшие на стенде, при этом теряются.
* **Telegram — OIDC-провайдер `telegram`:** адреса Telegram, код с PKCE S256, секрет по Basic, подпись — по ключам Telegram, userinfo выключен. **Просим только `openid profile`.** Номер телефона продукту не нужен — хватает `sub`, а лишние персональные данные — лишняя забота по 152-ФЗ. `telegram:bot_access` тоже не просим: писать человеку из бота — отдельная задача про уведомления.
* **Ключи бота — из окружения.** В реалме — подстановки `${TELEGRAM_CLIENT_ID}` и `${TELEGRAM_CLIENT_SECRET}`, значения — в `.env` (он в `.gitignore`), шаблон — `.env.example`. Keycloak подставляет их при импорте: сменить ключи — пересоздать реалм.
* **Первый вход — регистрация без анкеты.** Почта, имя и фамилия в профиле реалма необязательны. По умолчанию Keycloak требует все три, а у Telegram нет почты и часто нет фамилии — первый вход упирался бы в форму «заполните профиль». Профиль снят с работающего Keycloak — API администратора и экспорт реалма, — а не написан по памяти.
* **Страница входа Keycloak — по-русски:** язык реалма по умолчанию.
* **Адрес Keycloak закреплён** — `KC_HOSTNAME=http://localhost:8180`, переопределяется в `.env` (туннель, домен). От него строится адрес возврата `…/realms/selfin/broker/telegram/endpoint`, и он должен совпасть с Allowed URLs бота буква в букву.
* **Администратор Keycloak на стенде** — `admin` и `KC_ADMIN_PASSWORD` из `.env`, без него — `admin`, как у базы стенда.

## Не входит

* **Проверка токена нашим сервером** и владелец запроса — ANO-195; там же минимальный вход фронта, иначе экран получит 401 (комментарий в ANO-195).
* **Свой экран входа**, `kc_idp_hint`, тема Keycloak — ANO-152. Сейчас на странице Keycloak и кнопка Telegram, и форма логина с паролем; паролей у реалма нет — войти через форму некому.
* **Яндекс ID и VK ID; роли; Keycloak на сервере**, HTTPS, домен, резервные копии — «Выкладка».
* **Секрет в хранилище Keycloak (vault)** вместо подстановки при импорте — когда ключи начнут меняться чаще, чем пересоздаётся реалм.
* **Имя с символами из запретного списка Keycloak** — `<>&"$%!#?§;*~/\|^=[]{}()` — не пройдёт проверку профиля: первый вход попросит его поправить. Проверку по умолчанию не ослабляем.

## Как проверяется

| что | проверка | мутация |
|---|---|---|
| в реалме нет ключей бота; Telegram — код с PKCE S256, секрет по Basic, без userinfo, без телефона; почта, имя и фамилия необязательны | `tools/keycloak-realm.test.mjs` — в CI, джоба «Инструменты» | секрет в файле; PKCE выключен; телефон; userinfo; секрет в теле запроса; почта обязательна |
| стенд поднимает реалм из репозитория; страница входа по-русски, с кнопкой Telegram; кнопка уводит на oauth.telegram.org с кодом, PKCE S256, `openid profile`, нашим адресом возврата и Client ID | `tools/keycloak-check.mjs` против стенда | PKCE выключен; телефон; Telegram выключен; язык страницы |
| вход до конца: подтверждение в Telegram — человек в консоли учётной записи Keycloak | руками на стенде, бот владельца | — |

Живую проверку в CI не ставим: Keycloak там нет, а поднимать его ради одной проверки дорого. Ключи реалма держит статический тест, их действие — живая проверка: без ключа `pkceEnabled` Keycloak не шлёт PKCE, без `defaultScope` просит только `openid`.

## Тесты и мутации

* Красные до: статический — файла реалма нет; живой — Keycloak нет, соединение отвергнуто.
* Шесть мутаций статического теста — шесть красных своими утверждениями: секрет в файле, PKCE выключен, телефон, userinfo, секрет в теле запроса, почта обязательна. Сначала тот же тест на чистом файле — зелёный.
* Четыре мутации живой проверки — четыре красных своими строками: PKCE выключен — «PKCE S256 — null»; телефон — «openid profile phone»; Telegram выключен — нет кнопки; язык — страница не по-русски. Контрольный прогон до и прогон после мутаций — зелёные.

## Найдено по ходу

* **`${username}` в профиле — не подстановка окружения.** Подписи атрибутов профиля Keycloak хранит как `${username}`, `${email}` — ключи переводов, а импорт реалма читает `${…}` как переменную окружения. Проверено: неизвестную переменную импорт оставляет как есть, подписи после импорта на месте.
