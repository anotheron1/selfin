# Зеркало сверки — остаток сверяемого счёта (ANO-214)

PR 9 спринта 4 (`2026-10-03-sprint-4-plan.md`, раздел 3); карта C1, раздел 4 «Правки без развилки». Спека и план одним документом.

## Что на экране

Стенд `59f3daf`, 04.10.2026. «Дашборд» → «остаток обновлялся 36 дн. назад» → лист «Обновить остаток», счёт по умолчанию:

* «selfin считает: 59 900 ₽»;
* ввожу число банка по основной карте, 54 900 ₽, — «дрейф −5 000 ₽ за 36 дн.».

По расчёту на основной карте 54 900 ₽ — столько же пишут «Настройки» → «Счета». 5 000 ₽ — наличные «Эталон», отдельный счёт со слежением. Дрейфа нет, а лист его показывает. Поверив строке «selfin считает» и введя 59 900, человек положил бы наличные и в основную карту: «на счёте» стало бы 64 900. Лист закрыт без сохранения, сверок как было — 13.

## Почему

Лист берёт для зеркала `currentBalance` ответа `/pocket` — сумму всех свободных счетов: основная карта, прочие дебетовые и наличные со слежением (`PocketEngine.calculate`, шаг 1, `otherAccountsBalance`). А сверка пишется на один счёт — основной (`createCheckpoint` без `accountId`). Комментарий в листе прячет зеркало для неосновного счёта, а для основного считает сумму верной. Так только при одном свободном счёте.

## Решение

**Зеркало и дрейф — остаток сверяемого счёта по правилу карточки «Счетов»** (`AccountBalanceService.balanceAt`, поле `balance` в `/accounts`). Лист уже читает `/accounts` для выбора счёта. С этим же числом сервер потом считает дрейф в истории сверок: только у основного счёта и от его прошлой сверки (`BalanceCheckpointService.findAll`). Превью в листе и строка истории начинают говорить одно.

* **Основная карта со сверкой** — её остаток из `/accounts`. На стенде: «selfin считает: 54 900 ₽», ввод 54 900 — «дрейф 0 ₽ — расчёт сходится».
* **Основная карта без сверки** — как сейчас: подпись «расчёт selfin по записанным фактам» и число карточки, дрейфа нет. У счёта без сверки `/accounts` молчит — так решено раньше (спека счетов, §6). Сервер для первой сверки дрейф тоже не считает.
* **Прочий счёт** — без зеркала, как сейчас: факты его не двигают, сервер дрейф для него не считает.
* **Пока список счетов не пришёл** — зеркала нет. Иначе первую долю секунды лист показывал бы число карточки, и дрейф прыгал бы.

Выбор числа — чистая функция в `lib/reanchor.ts` рядом с подписью и строкой дрейфа: тестируется без компонента.

## Не закрывает

* **Основная карта без сверки при прочих свободных счетах со сверкой.** Подпись «по записанным фактам» включает их остатки — то же число, что карточка. Дрейфа там нет, но число подписи завышено на остатки прочих счетов. Случай узкий: человек сверил наличные, а основную карту — ни разу. Правильное число — факты основной карты с нуля (ANO-28) — сервер наружу не отдаёт. Карточку без сверки переименовывает ANO-216 (PR 8); если понадобится, число подписи — туда же.

## Как проверяется

| что | тест | мутация |
|---|---|---|
| основная карта со сверкой — её остаток из `/accounts`, а не сумма свободных | `reanchor.test.ts`, `mirrorBalance` | число карточки для основной карты со сверкой |
| без сверки — число карточки | там же | без сверки — пусто |
| прочий счёт — зеркала нет | там же | зеркало для прочего счёта |
| список счетов не пришёл — зеркала нет | там же | зеркало до загрузки — числом карточки |
| лист показывает подпись и дрейф по `mirrorBalance`, а не по числу карточки | сторож по исходнику `ReanchorSheet.tsx` | дрейф снова от `currentBalance` |

Изменение только во фронте: тест фронта на поведение функции и сторож по исходнику на её подключение — компонентных тестов во фронте нет.
