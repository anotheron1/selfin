# Ворота видят замечание Codex в теле ревью (ANO-204)

Поправка к воротам 1–2 ANO-194, спека `2026-09-26-pr-ready-gate-design.md`. Спека и план одним документом: шагов немного.

## Что сломано

Раздел 5 спеки ворот называл это ограничение прямо: «Замечание в теле ревью, а не в строке кода. Скрипт считает только ветки обсуждения. За 32 PR Codex так не писал ни разу». 27.09 на #96 написал.

Повторное ревью Codex 02:20 по голове `8420b0f` пришло одним ревью без веток. Замечание P2 «Validate withdrawals against the balance on their date» лежит в теле ревью со ссылкой на `TargetFundService.java#L465`. Строка 465 в диффе PR не менялась — привязать ветку было не к чему. `bash tools/pr-ready.sh 96` в это время говорил:

```
Codex            да   ревью 2026-09-27 02:20 — голова 8420b0f просмотрена
Замечания Codex  да   без ответа нет
Итог: готово
```

`unansweredThreads` читает только ветки (`pulls/{n}/comments`). Ревью Codex участвует только как вердикт «голова просмотрена» (`codexState`), значки `![P… Badge]` в его теле не смотрит никто. Та же функция стоит в джобе «Codex — все замечания отвечены» — она тоже зелёная. Замечание я увидел глазами, читая ревью.

Это ровно тот сбой, ради которого строились ворота 1–2: «замечание Codex без ответа влито».

## Как мерил

* **Ревью #96** — `gh api repos/anotheron1/selfin/pulls/96/reviews`: последнее ревью Codex, 02:20, коммит `8420b0f`, в теле — строка со значком P2 и ссылкой на строку файла. Веток у него нет: `pulls/96/comments` после 02:17 — пусто.
* **Вывод ворот** — `bash tools/pr-ready.sh 96`, прогон 27.09 около 04:50, до моего ответа: блок выше. Время здесь и в скрипте — UTC.
* **Как Codex пишет раньше** — раздел 1 спеки ворот: в 18 ревью за 32 PR тело — только шапка, номер коммита и блок «About Codex».

## Решение

* **Замечание в теле ревью — такое же замечание.** Каждая строка тела ревью Codex со значком `![P… Badge]` — отдельное замечание; заголовок — текст строки без разметки, как у ветки.
* **Ответ — наше слово после ревью, в котором есть заголовок замечания.** Ветки у такого замечания нет, отвечать больше некуда. Засчитываются комментарий в ленте PR и своё ревью с текстом — оба с аккаунта не Codex, оба позже ревью с замечанием. Заголовок в ответе — чтобы ответ относился к этому замечанию, а не к любому соседнему.
* **Ответ удобнее давать ревью:** `gh pr review <N> --comment --body-file …`. Событие ревью перезапускает джобу само. Комментарий в ленте джобу не перезапускает — на `issue_comment` она не подписана, такой прогон привязывается к `main` (спека ворот, раздел 3). После ответа в ленте без пуша — перезапустить джобу руками: `gh run rerun <id> --failed`.
* **Вывод:** в пункте «Замечания Codex» — `тело ревью ЧЧ:ММ P2 Заголовок`, рядом с ветками.
* **`--at`** — как у веток: ревью и ответы позже заданного момента не в счёт.

## Правила продукта — сверка

Правка — инструмент разработки: скрипт ворот и его тесты. Экранов, расчёта и данных пользователя не касается.

| правило | как соблюдено |
|---|---|
| 1–4, запреты | не затрагиваются: ни бюджетов, ни отчётов план-факт, ни обещаний, ни пейволла |
| 5–9, требования | не затрагиваются: поведение продукта не меняется |
| 10–13, тексты на экране | не затрагиваются: вывод скрипта видят разработчики, не пользователи |
| характер плановой строки | не затрагивается |
| данные респондентов | не затрагиваются. В тестах — номера, логины и время из публичной истории PR этого репозитория |

## Чего не ловит

* **Качество ответа** — как и у веток: проверяется, что ответ есть и назван заголовком, а не что он по существу.
* **Ответ на два замечания одним комментарием** засчитывается обоим, если в нём оба заголовка. Это правильно: ответ и есть на оба.
* **Заголовок, процитированный до ревью**, — не ответ: считается только слово после ревью. Заголовок, повторённый позже по другому поводу, засчитается — по невнимательности так не пишут.
* **Codex перепишет заголовок в следующем ревью** — это новое замечание, со своим ответом.

## Мутации

По одной на итоговом коде; файл возвращён и перепроверен прогоном тестов.

| # | мутация | краснеет |
|---|---|---|
| G1 | ответ Codex засчитан | «комментарий Codex с тем же заголовком — не ответ» |
| G2 | ответ до ревью засчитан | «заголовок в ленте до ревью — не ответ» |
| G3 | ответ без заголовка засчитан | «ответ без заголовка», «в теле два замечания» |
| G4 | из тела берётся только первое замечание | «в теле два замечания» |
| G5 | своё ревью — не ответ | «ответ своим ревью с заголовком — засчитан» |
| G6 | `--at` не режет ответы | «`--at`: …» |
| G7 | `--at` не режет ревью | «`--at`: …» |
| G8 | пункт не видит тело ревью | «пункт «Замечания Codex» — и ветки, и тело ревью» |
| G9 | каждая строка тела — замечание | десять из десяти новых |

Первый прогон G4, G5 и G9 не лёг: шаблоны многострочные, а файл в рабочей копии — с CRLF. Перегнаны после приведения концов строк; скрипт мутаций пишет «МУТАЦИЯ НЕ ЛЕГЛА», а не «выжила», — пропуска видно.
