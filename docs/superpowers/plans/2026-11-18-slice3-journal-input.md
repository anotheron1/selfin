# Срез 3 — журнал и ввод: план

**Цель:** журнал на деталях дизайн-системы по доскам холста лица; трата сама встаёт к ожиданию; форма «+» одной суммой; карточка записи с правкой даты и категории, дублем и серией; поиск; один порядок категорий и «Категории» с правилом.

**Спека:** `docs/superpowers/specs/2026-11-18-slice3-journal-input-design.md` — номера пунктов «п. N» ниже ведут туда.

**Стек:** Java 21 / Spring Boot, React 18 / TypeScript, vitest, JUnit 5 + Testcontainers.

## Общие условия

* Сборка: `JAVA_HOME="/c/Users/Kirill/.jdks/jbr-21.0.8" ./mvnw verify` из `backend` — юниты и IT; фронт — `npm test -- --run`, `npx tsc --noEmit`, `npm run build` из `frontend`.

### Задача 1.2. Трата встаёт к ожиданию (п. 1)

* Правило — одна чистая функция: запись (дата, категория, тип, вид) и строки-кандидаты с погашенным → строка или ничего.
* Юниты на каждую ветку: своя неделя — последняя строка не позже записи; шестой день назад — встаёт, седьмой — нет; строка впереди в том же месяце — ближайшая; в следующем месяце — нет; разовое ожидание собирает траты до своей даты; бронь и хотелка не встают; погашенная целиком строка — не кандидат; другой тип, другая категория, удалённая строка — нет.
* `createStandaloneFact` проставляет `parentEventId` по правилу и зовёт `resettlePlan`.
* IT: `POST /events/facts` в «Продуктах» при ожидании недели — у записи `parentEventId`, «Свободно» прежнее; бронь той же категории — записи без плана; удаление записи («Отменить») возвращает строке её сумму.

### Задача 1.3. Дата, категория и вид у записи (п. 2)

* `FinancialEventUpdateFactDto` — ещё `date`, `categoryId`, `priority`.
* Проверки — 400: дата позже сегодня; категория удалена или другого типа; смена категории у записи к брони или у перевода в копилку.
* Дата или категория сменилась — правило задачи 1.2 заново: запись уходит к другой строке ожидания или выходит из плана, `resettlePlan` у старой и новой строки. Запись к брони держит бронь. У перевода в копилку движение копилки идёт за датой (`syncTransferMovement`).
* Юниты на каждую проверку и переход; IT `PATCH /events/{id}/fact` с датой и категорией.

### Задача 1.4. «Больше не нужно» — `closePlan` (п. 3)

* `FactCreateDto.closePlan`. В той же транзакции, что запись: сумма плана — погашенное, план исполнен. Только у брони, расход и доход; у ожидания и хотелки — 400. У серии — одна строка, правило не меняется.
* Юниты; IT: бронь 10 000, запись 7 000 с `closePlan` — план 7 000, исполнен, «Свободно» на 3 000 больше, чем без признака.

### Задача 1.5. Серия со сменой числа (п. 5)

* IT: серия 12-го, `PUT … scope=ALL` и `FOLLOWING` с 15-м — 200, ответ — строка 15-го того же месяца.
* Правка: после `regenerate` ответ ищется по периоду правленой строки, а не по старой дате (`FinancialEventService.update`, `findActiveByRuleAndDate`).
* IT «Закончить серию» для PR 5: `FOLLOWING` с концом серии на дату строки — строки после неё сняты, эта осталась. Падает — правка здесь же.

### Задача 1.6. Мутации, стенд, PR

* Мутации — каждая ветка правила 1.2, граница шести дней, «тот же месяц», характер, тип, категория, погашенная строка, погашение 1.1, каждая проверка 1.3, `closePlan`, ответ 1.5.
