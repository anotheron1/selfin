# Selfin MCP

## HTTP MCP в Compose

Compose из `deploy` запускает Selfin, Keycloak и MCP с профилем `mcp`.
Задай `SELFIN_PUBLIC_URL`, отдельный случайный
`SELFIN_MCP_CLIENT_SECRET` и точный `SELFIN_MCP_OAUTH_REDIRECT_URI` из настроек клиента.
Для локального экземпляра используй отдельное имя проекта и тег образов.

```sh
docker compose -p selfin-mcp-local --env-file deploy/.env -f deploy/docker-compose.yml --profile mcp up -d --build frontend mcp
```

В локальной рабочей папке создай `deploy/.env` по `deploy/.env.example`. Укажи
`SELFIN_TAG=mcp-local`. Например, для
`SELFIN_HTTP_PORT=8280` укажи `SELFIN_PUBLIC_URL=http://127.0.0.1:8280`. На сервере
укажи внешний HTTPS-адрес Selfin. Настройка OAuth запускается тем же Compose и
регистрирует в Keycloak клиент для входа и клиент обмена токенов.

Подключи Streamable HTTP сервер по адресу `SELFIN_PUBLIC_URL/mcp`.
Для входа используй зарегистрированный `SELFIN_MCP_OAUTH_CLIENT_ID`
(по умолчанию `selfin-mcp-codex`). В Codex CLI можно добавить HTTP-сервер с
`--oauth-client-id`, затем подключить его кнопкой Authenticate или командой
`codex mcp login <имя>`. В Keycloak регистрируется весь адрес возврата, включая
суффикс, который Codex может добавить к пути callback. Подключение
может запросить `selfin-mcp:read` и `selfin-mcp:write`. Запись по-прежнему
требует подтверждения конкретного платежа в MCP-клиенте.

Внутри Compose MCP обращается к `http://backend:8080` и
`http://keycloak:8080/auth/realms/selfin`. При переносе MCP на другую машину эти
адреса задаются переменными `SELFIN_MCP_BASE_URL` и
`SELFIN_MCP_ISSUER_INTERNAL`. Прокси направляет на новый сервер те же публичные
маршруты `/mcp` и `/.well-known/oauth-protected-resource/mcp`.

Локальный MCP-сервер для Selfin. `get_available_money` без аргументов возвращает «Свободно» до ближайшего дохода, фактическую дату горизонта и строки расчёта из `GET /api/v1/pocket`. Суммы передаются десятичными строками в рублях. При отсутствии последней сверки поле `checkpointDate` опускается.

`preview_expense` рассчитывает «Свободно» до и после одной будущей покупки через штатную «Примерку» Selfin. Передай сумму и дату покупки в формате `YYYY-MM-DD` или `tomorrow`. Если покупка позже конца исходного периода до ближайшего дохода, инструмент показывает этот период и отдельное сравнение до даты покупки. `horizonEndDate` задаёт точную дату конца, а `keepHorizon=true` сохраняет ограничение ближайшим доходом. В обоих случаях вне выбранного периода показывается граница расчёта. Для отдельной команды добавить покупку в план используются `prepare_plan` и `save_plan`.

`search_expenses` показывает число и точную сумму записанных расходов, разбивку по месяцам и категориям. Пара `from` и `to` задаёт включительный период. Без неё используется текущий месяц по календарю Selfin. `text` ищет слова по названию и категории, `categoryId` ограничивает категорию. При `includeEntries=true` инструмент выдаёт до 200 свежих строк и признак ограничения. Итоги охватывают все совпадения. `get_plan_fact` показывает штатное месячное сравнение плана и факта по явной просьбе. Поле `type` ограничивает отчёт расходами или доходами.

В план можно добавить разовые и ежемесячные расходы и доходы одним списком. `get_plan_context` читает категории и подходящие строки за целевой месяц. Для предложения суммы или даты он может читать историю за три относящихся к запросу календарных месяца. `prepare_plan` проверяет весь список и возвращает его вместе с идентификатором черновика. `save_plan` показывает сформированную сервером форму с точными строками. Selfin получает запросы записи после явного подтверждения всей формы. Перед первой записью MCP повторно проверяет актуальность данных.

Для подготовки и записи плана нужен Selfin с маршрутом `GET /api/v1/events/indefinite-plan-rules`. Он позволяет обнаружить совпадение с будущим платежом по бессрочному правилу, когда строки за нужную дату ещё нет в журнале.

Ежемесячный повтор указывается по явной просьбе пользователя через `monthly.dayOfMonth` и необязательную включительную дату `monthly.endDate`. Поле `date` содержит дату первого платежа. Для повтора каждого 31-го с февраля 2027 это `date: "2027-02-28"` и `monthly.dayOfMonth: 31`. Правило и платежи создаёт Selfin. MCP подтверждает результат по ID правила и ID первого платежа.

`get_month_plan_context` читает целевой план и до года записанных трат для запроса «Помоги спланировать декабрь». По умолчанию выводит помесячные суммы за 12 завершённых месяцев и примеры из того же месяца год назад. Режимы `plan` и `history` позволяют запросить один источник. Пара `historyFrom` и `historyTo` задаёт включительные даты истории, а `categoryId` — одну категорию. Ответ отмечает неполный месяц и ограничение списка примеров. Помесячные суммы считаются по всем найденным записям. Выбранные человеком новые события проходят через `prepare_plan` и `save_plan`.

`prepare_fact` готовит одну уже случившуюся обычную трату. Дату можно передать как `today`, `yesterday` или `YYYY-MM-DD`. Для самостоятельной траты укажи действующую `categoryId`. Selfin подбирает подходящее ожидание. Для оплаты конкретной плановой строки нужны её `planId` и `planDate`. Selfin относит частичную оплату к выбранному платежу и сохраняет остаток брони. `save_fact` запрашивает подтверждение и возвращает сохранённую трату с её фактической связью. Для исхода `unknown` повтори тот же `draftId` в той же сессии.

## Сборка

Из корня Selfin с JDK 21:

~~~powershell
.\backend\mvnw.cmd -f mcp/pom.xml verify
~~~

В Linux и Git Bash используется `./backend/mvnw -f mcp/pom.xml verify`. Готовый JAR находится в `mcp/target/selfin-mcp.jar`.

## Запуск в локальном Codex

Перед запуском клиента передай в окружении `SELFIN_MCP_BASE_URL` с origin тестового API и `SELFIN_MCP_ACCESS_TOKEN` с короткоживущим токеном зарегистрированного тестового человека. Origin включает схему, хост и порт. HTTP поддерживается на loopback, для остальных адресов используется HTTPS. Токен передаётся через окружение дочернего процесса.

В конфигурации локального клиента можно указать:

~~~toml
[mcp_servers.selfin_local]
command = "C:/path/to/jdk-21/bin/java.exe"
args = ["-jar", "C:/path/to/selfin/mcp/target/selfin-mcp.jar"]
env_vars = ["SELFIN_MCP_BASE_URL", "SELFIN_MCP_ACCESS_TOKEN"]
enabled_tools = ["get_available_money", "preview_expense", "search_expenses", "get_plan_fact", "get_plan_context", "get_month_plan_context", "prepare_plan", "save_plan", "prepare_fact", "save_fact"]
default_tools_approval_mode = "writes"

[mcp_servers.selfin_local.tools.save_plan]
approval_mode = "approve"

[mcp_servers.selfin_local.tools.save_fact]
approval_mode = "approve"
~~~

Настройка для `save_plan` и `save_fact` позволяет Codex открыть MCP-форму без второго, общего запроса на запуск инструмента. Подтверждение записи внутри вызова запрашивает сам сервер. Codex должен поддерживать MCP form elicitation. Используй интерактивную локальную сессию с тестовым профилем.

## Сквозные проверки

- Спроси «Сколько свободно до следующего дохода и почему?». Сравни `available`, `horizon.endDate` и `horizon.fallback` с прямым запросом для того же профиля. В `breakdown` передаются типы, подписи и суммы строк основного расчёта до итога.
- Примерь покупку после ближайшего дохода. Сверь исходный период и отдельное сравнение до даты покупки с прямыми расчётами Selfin. Затем повтори с явной датой конца до покупки и проверь, что сохраняется заданный период.
- Попроси найти обеды за месяц, затем отдельно сравнить план и факт расходов за тот же месяц. Сверь итоги поиска с журналом, а сравнение — со штатным отчётом Selfin.
- Назови две новые строки плана. Сверь обе строки в форме, отклони её и перечитай журнал. Повтори с согласием. В журнале должны появиться ровно две записи с показанными реквизитами.
- Попроси помочь спланировать месяц с ежегодной покупкой год назад и с тратами на машину несколько месяцев подряд. Сверь целевой план и историю с журналом. Выбери одну предложенную строку и проверь её отдельно в форме сохранения.
- Запиши обычную трату из подходящего ожидания и отдельно частичную оплату выбранной строки серии. Сверь фактические связи и остаток брони в журнале Selfin.
- Для исхода `unknown` повторно вызови `save_plan` с тем же `draftId` в этой сессии. Сохранившиеся строки возвращаются из результата, для неясных строк сохраняются прежние ключи попыток. Черновики живут в процессе MCP. После его перезапуска сначала сверь журнал и подготовь новую попытку, если она нужна.
